# 留言板：Solana Epitaph 定位候选评估

日期：2026-10-30。来源：用户提供的完整定位底稿。本文件整理新方向与工程取舍，不代表已确认改名或已实现。

## AI交接
用户新增方向：Solana Epitaph／赛博墓石／链上墓志铭，情绪表达与纪念、镌刻仪式、单栏黑曜石风格、链上元数据、9:16分享海报、早期编号与计数。
正式项目名称暂保留此前明确要求的「留言板」；新名称为候选。此前已确定的登录界面、主题切换、语言设置、移动钱包兼容保留。尚未执行新界面或交易代码。

## 产品建议
建议把表达重点收敛为：“为一句值得留下的话，做一份可核验的链上记录。”
产品从泛闲聊转向纪念、告别、承诺和个人记录，作为待验证的产品定位假设。墓志铭的意象可用于视觉探索，但可能让用户以为仅用于逝者纪念，不能未经验证就假设能提高留存或传播十倍。
保留Threads式清楚的信息流与熟悉操作；情绪文案用于引导和发布确认，设置、连接钱包、错误提示仍用易懂术语。不要为了仪式感把所有按钮改成生僻称呼。

## 建议吸收的设计
- 单栏公共流，暗色背景候选#09090b、细边框、约580px最大阅读宽度；手机随屏幕缩放，不固定580px。正文以可读为准，短句可居中，长中文按阅读效果决定。
- 元数据使用等宽字体，正文采用无衬线字体，保留浅色和跟随系统方案及可访问对比度。
- 交易核验入口展示真实公钥、网络和签名；“已确认”只指交易校验状态，不代表平台背书、法律公证或永久可访问。
- 输入前可提供告别、纪念、承诺等可跳过的提示，明确内容公开且可能与钱包关联。不要把公共链误称为保密树洞，不引导上链密码、联系方式或他人隐私。

## 必须修正的承诺与字段
1. 永久性：“永久免除审查与遗忘”“全网节点永存”不能作为工程保证。Devnet可能重置；历史可取取决于节点服务和保留，站点也可过滤展示。不可篡改不等于随时可访问，更不等于保密。
2. 发送状态：广播不是成功。确认窗应在签名前说明公开性和修改边界，真正成功必须核验交易。确认不确定时保留查询入口，不诱导重复提交。
3. 编号：现有Memo加板级地址方案没有强制的全局递增编号。客户端排序得到的#000042会因分页/漏读而变化，不能当永久编号或稀缺席位。首版使用交易签名作为稳定核验标识；若确需唯一递增序号，需要另评估索引或链上状态方案及成本。
4. 计数：只取到一页不能称总数。可显示“已加载42条”；全量完整核验后才能说明已核验数量。“42/100”仅在真实定义了100条目标或限额时使用，不能伪造名额紧缺。纯前端不能强制全链100条上限。
5. 高度与时间：getTransaction返回slot和可为空的blockTime；slot不能直接标为block height。首版准确写Slot，UTC时间从真实数据转换，未知则写未知。确需区块高度另取对应字段。
6. 字符边界：沿用已验证的140个Unicode grapheme clusters与560个UTF-8正文字节双限制，并校验完整交易体积，不能简化成任意140字符必定可发。

## 建议的发布确认文案
“这段文字将公开写入Solana Devnet测试网络，并与签名钱包地址关联。交易确认后，本应用无法修改或撤回原记录。测试网可能重置，不保证永久保存。请勿发布秘密或个人敏感信息。”
确认界面同时展示正文预览、网络、费用估算和返回修改入口；不默认自动确认钱包。主网文案须在另行决定主网后重审。

## 增长功能分期
- 1.1A原型：对比普通公共留言流与纪念铭文方向；设计首页、登录、主题/语言设置、发布确认、成功状态及海报预览。模拟数据明确标注。
- 阶段2：落实发布确认和真实状态，先跑通交易闭环。
- 阶段3：完成真实公共流与单条可定位详情；随后拆独立分享海报工单。海报只使用已核验内容，建议9:16，二维码直达可核验详情或正确网络的Explorer；不把钱包连接成功当成可出具存证的证据。
- 阶段4：真机验收导出长中文/emoji排版、图片清晰度、二维码、网络标记、缺失时间和可访问性；不自动替用户发布到社交平台。
- 精确全局计数、永久递增编号及100名额机制后置评估，不为营销临时推翻无后端/无自定义程序边界。
增长假设：海报可能增加分享意愿，需观察发布完成率、主动导出/分享意愿等，不能保证自传播。

## 2026-10-30：Sprint 1.0 实现取舍

- 钱包特性仅使用 standard:connect、standard:disconnect、standard:events；仓库未安装 @wallet-standard/features，因此在 wallet.ts 内声明这三个最小契约，不新增依赖，也不引入旧版 wallet-adapter。
- 连接态使用单调递增 generation：断开、账户清空、钱包取消注册、dispose 都使旧连接结果失效；连接进行中重复点击直接忽略，不并发弹窗。
- 账户切换只更新快照中的地址；余额读取由 React 层以地址为依赖重建 AbortController 并取消旧请求，避免旧余额覆盖新账户。
- 网络状态只表示“应用查询的 RPC 是 Devnet”；账户 chains 包含 solana:devnet 仅按能力筛选，不显示为钱包当前网络。
- 余额读取先用 isAddress 校验；RPC 失败抛错，绝不返回0。超时生产固定10秒，仅测试可注入更短超时。
- 测试主体使用 node 环境与假钱包/假 RPC；REVIEW-1.0 新增 jsdom + Testing Library 仅用于视图回归，不搭建 E2E；真实钱包操作仍由用户验收。
- 页面不提供签名、交易构造/发送、留言输入或历史列表入口。

## 2026-10-30：REVIEW-1.0 R1/R2 修复取舍

- R1 将“页面取消等待”和“钱包请求是否结束”分开：`cancelConnect` 只使页面 generation 失效并清除本地连接显示，不调用 `standard:disconnect`，也不声称已关闭钱包弹窗或撤销授权。控制器按钱包名记录 `pendingConnectWallets`；同一钱包的底层请求未结束前不再调用 `connect`（避免并发弹窗），其他钱包仍可正常连接；请求的 `finally` 只更新等待列表，不覆盖新一轮状态。
- App 的操作锁由单一 `busy` 布尔改为递增 action 序号。取消时递增序号并清空 active action，旧 connect 的 finally 只能清理自己的 action，不能解锁后来发起的操作。
- R2 将余额视图拆成以 `${address}:${attempt}` 为 key 的 `BalancePanel`；网络校验状态也记录其对应地址。换账户或重试时组件同步重建，旧余额、旧错误和旧 loading 都没有展示路径；旧请求仍通过 AbortController 取消。
- 新增精确测试依赖 `@testing-library/react@16.3.3`、`@testing-library/dom@10.4.2`、`jsdom@30.1.3`；只做 jsdom 组件回归，不引入 E2E 或浏览器自动化。真实钱包、真实时序和窄屏仍由用户人工验收。

## 阶段0必须延续的经验

1. Phantom需要明确的Testnet Mode → Solana Devnet指引；应用RPC为Devnet不等于钱包当前显示已核验。
2. 每次连接显示完整公钥，切换账户后旧余额和旧异步结果立即失效。
3. Memo4在本次实验的140中文/emoji样本中通过；旧Memo3默认计算预算曾失败。此结论留给后续写入工单，当前不引入Memo依赖。
4. 钱包会在发送时附加ComputeBudget指令和优先费，后续读取器不能假设交易只有两条指令；估算基础费不等于最终费用。
5. Devnet可能重置，公共RPC历史保留未知；不宣传永久可访问。

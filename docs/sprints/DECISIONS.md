# 技术决策

## 2026-10-31：2.2A二审剩余R3/R4修复取舍

- 终态判定按确认级别分层：只有`confirmed`/`finalized`可结算，成功必须显式`err === null`，仅对象形态的明确错误写`failed`。`processed`仍可能回滚，null/未知级别及缺失、畸形err只作待确认观察；不新增确认等级，不改变原签名回执与恢复语义。
- 钱包能力事件只作为期望值，不与实时getter永久二选一。每次取/用会话同时核对事件值、钱包实时chains/features、当前账户chains/features、地址/公钥和版本；不一致时保守失效签名授权但保留只读连接，避免旧事件或原地变更绕过复核。
- 测试假钱包正常路径先同步公开属性再发事件；另用不配对事件验证拒绝路径。新增组合回归保持零签名/零广播，B与真实钱包操作继续关闭。
- 本轮仅改2.2A核心、必要回归和文档；R1/R2/R5已关闭实现、读取核心、视觉与依赖不变，工作区停交Codex复审。

## 2026-10-31：Sprint 2.2A 发布核心实现取舍

- 只交 A：新增独立 `publisher.ts` 与注入测试，扩展 `wallet.getSigningSession()` 和 simulation 待签字节；页面不实例化 publisher，不接发布 UI，不调用真实钱包签名或广播。
- 签名会话绑定连接成功的 Wallet/WalletAccount 对象与单调 revision；地址、32 字节公钥、Devnet、`standard:signTransaction`、v0 支持与账户能力同时核对。连接/取消/断开/账户能力/注销/dispose 都使旧会话失效，不按钱包名重建签名者。
- 准备阶段使用 simulation 返回的同一笔 wire/message，重建并逐字节比对；签名前、钱包返回后、回执后广播前均重查固定 Devnet genesis、原 blockhash 有效高度、原消息费用与余额。过期/换价一律重新准备，不自动再签。
- 签名返回按 unknown 校验单输出、Uint8Array、大小、尾随字节、唯一作者槽、messageBytes 和全零签名，并用 Kit `verifySignature` 做真实 Ed25519 验签；API 不可用即拒绝，不手写密码学、不降级为“签名存在”。
- 广播前同步写最小版本化回执（最多10条，优先清最旧终态），再调用一次 `sendTransaction`。签名槽在任何异步复核前占住，修复并发提交重复广播；回执后复核失败标 `not_sent`，响应不确定保留原签名标 `uncertain`，不自动重发、不换 blockhash。
- 确认只查原签名并区分 processed/confirmed/finalized/error/expired；恢复零钱包零广播；读回按原签名核对作者。准备快照与回执都在使用前严格校验数值/格式；A 的注入测试和 Node 验签不等于真实钱包/浏览器兼容验收，B 仍需持有者单笔 Devnet 操作。

## 2026-10-30：REVIEW-1.0 R1/R2 修复取舍

- R1 将“页面取消等待”和“钱包请求是否结束”分开：`cancelConnect` 只使页面 generation 失效并清除本地连接显示，不调用 `standard:disconnect`，也不声称已关闭钱包弹窗或撤销授权。控制器按钱包名记录 `pendingConnectWallets`；同一钱包的底层请求未结束前不再调用 `connect`（避免并发弹窗），其他钱包仍可正常连接；请求的 `finally` 只更新等待列表，不覆盖新一轮状态。
- App 的操作锁由单一 `busy` 布尔改为递增 action 序号。取消时递增序号并清空 active action，旧 connect 的 finally 只能清理自己的 action，不能解锁后来发起的操作。
- R2 将余额视图拆成以 `${address}:${attempt}` 为 key 的 `BalancePanel`；网络校验状态也记录其对应地址。换账户或重试时组件同步重建，旧余额、旧错误和旧 loading 都没有展示路径；旧请求仍通过 AbortController 取消。
- 新增精确测试依赖 `@testing-library/react@16.3.3`、`@testing-library/dom@10.4.2`、`jsdom@30.1.3`；只做 jsdom 组件回归，不引入 E2E 或浏览器自动化。真实钱包、真实时序和窄屏仍由用户人工验收。

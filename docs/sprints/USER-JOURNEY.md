# Said：端到端用户旅程与账号模型（v1 草案）

日期：2026-10-31。性质：开发暂停期完善的产品流程与身份模型设计稿，供逐条确认与后续工单拆分；未开始实现。

## 一句话定位
Threads 式的公共信息流体验，用区块链做身份与存证：账号就是钱包公钥，登录就是连接钱包，发布就是签名上链，历史就是链上可查。首版是网页 DApp；原生 App 是后续候选方向，不在本轮实现。

## 身份模型（重要边界）
- 用户视角：账号 = 公钥，密码 = 助记词。
- 实现边界：DApp 永远不接触、不收集、不要求输入助记词、私钥或钱包密码。密钥只存在用户钱包里，DApp 只拿公钥并请求签名。“密码=助记词”是心智模型，不是站内功能。
- 推论：换钱包 = 换账号；丢助记词 = 丢号且平台无法找回；一个钱包可连多个 DApp；平台不建用户名、密码或手机号数据库。
- 未来原生 App 同样遵守：密钥由钱包或系统安全区管理，不自己发明密码登录。

## 端到端旅程（每步都要求可成功、可失败、可恢复）

### 0 进入页面
- 正常：打开 URL → 静态资源加载 → 壳先渲染（主题防闪烁）→ 首页直接读公共流，无需钱包。
- 异常：静态资源失败（白屏）→ 显示错误与重试；RPC 不可用 → 公共流显示真实失败，不假空。
- 缺口：真实公共流未接（当前是示例数据）。

### 1 浏览（未连接）
- 正常：看他人留言、点详情（完整公钥、区块/时间、Explorer 链接）、翻页/加载更多。
- 异常：RPC 限流或超时 → 明确错误 + 重试；节点无历史（getTransaction 返回 null）→ 标注不可得，不伪造。
- 缺口：全部随阶段 3 实现。

### 2 连接钱包
- 正常：发现钱包 → 选择 → 钱包弹授权 → 同意 → 显示公钥 + Devnet 校验 + 余额。
- 异常：无钱包（引导安装）；拒绝、取消、超时；切账户；钱包侧断开；网络错——各有明确状态与恢复路径。
- 再进入：授权记忆交给钱包；DApp 不持久化私密授权，进入后按当前钱包连接状态显示。
- 已实现：1.0 大部分及 R1/R2；缺口：真机拒绝/取消、切账户、系统与钱包版本记录（1.1B 尾巴）。

### 3 读公共流（所有用户共享）
- 正常：按板级标记地址取签名列表 → 取交易 → 校验程序、协议与作者签名 → 解析正文、作者、区块与时间 → 去重排序 → 分页。
- 再进入/换设备：无本地缓存也能读回（链是唯一真相源）。
- 缺口：全部待实现（阶段 3）。

### 4 我的历史发言
- 正常：用“由交易签名推导的作者公钥 == 当前钱包公钥”过滤，只显示自己的；空态提示“还没有留言”。
- 换钱包 = 换“我的”。
- 缺口：待实现（阶段 3 的一部分；当前“我的”是占位空态）。

### 5 发布留言
- 正常：输入（140 字/560 字节/非空白，已校验）→ 审阅 → 检查交易（构造 + 估费 + 模拟，已实现）→ 冷色确认不可撤回 → 钱包签名（2.2 未开）→ 广播 → 轮询确认 → 成功。
- 异常：余额不足、blockhash 过期、拒签、网络超时、确认不确定、重复点击——各有明确结果，不乐观冒充成功、不盲目自动重发。
- 成功后：刷新即出现在公共流与“我的”。
- 已实现：2.1 构造模拟；缺口：2.2 签名发送。

### 6 设置与偏好
- 主题本地持久化（已实现）；语言默认按浏览器或系统自动识别，手动切换可覆盖并本地持久化；日期格式待确认；跨设备同步不在首版。

### 7 再进入与跨设备
- 链是唯一真相源：任何设备、新会话都能读回他人与自己的历史。本地偏好不跨设备。账号身份随钱包走，不随设备走。

## 成功标准
每一步都有可观察结果；失败有明确提示与恢复路径；不把模拟当成功、不把示例当链上、不把连接当身份认证。

## 缺口与建议顺序
- 优先阶段 3 读取（公共流 + 我的），阶段 0 已有 2 作者 3 条真实留言可作测试数据，无需先等 2.2。
- 其次 2.2 签名发送；之后阶段 4 集中回归异常与兼容矩阵；阶段 5 发布。
- 1.1B 剩余真机项（拒绝/取消、切账户、系统与钱包版本）在 2.2 放行前补或明确跳过。

## 未来 App（候选，不在本轮）
账号 = 公钥、密码 = 助记词的原生 App；密钥管理沿用钱包或系统安全区；分享海报、昵称/头像等作为后续独立需求评估，不在首版堆叠。

# SPRINT-2.2B：单条Devnet留言发布页面

## 目标与前置

把已审过的2.2A发布核心接入现有页面，完成一条短留言的“审阅 → 用户钱包确认 → 真实确认 → 刷新读回”。这是v0.1之后的下一版本候选，不重开v0.1验收。当前状态与逐条证据只写根STATUS.md。

先读正式Obsidian项目档案AI交接、AGENTS.md、STATUS.md、DECISIONS.md，再检查git status。仓库已有用户的AGENTS/.clinerules及未跟踪规则/技能/记忆/钩子改动，保留原样；.workflow.lock是采用清单，不当作运行锁。只允许Cline一个实现者。

## 实现契约与范围

- 复用src/publisher.ts的prepare/sign/submit/confirm/check/recover/readBack、现有receiptStore、wallet.getSigningSession()和history客户端。精确接口以源码为准，不重写发布核心，不另建发送实现。
- 以src/App.tsx、src/Preview.tsx、src/i18n.ts为主要修改点；可新增一个薄的发布状态hook或结果组件，styles.css只做必要布局。不要为本单重构历史读取、钱包或发布核心；若确有主路径接口阻塞，记录具体证据和最小改动建议后交Codex判断。
- 沿用当前编辑/审阅样式。准备后显示Devnet、完整付款公钥、原正文、预估费用与公开不可撤回提示。费用是测试SOL，不宣称固定费用或永久免费。
- 只有用户主动点击“签名并发送”才能调用既有签名/提交流程。必须使用同一准备对象及钱包会话；正文/账户变化先失效旧准备。连点不得派发两次，等待钱包时显示明确状态。
- 钱包拒绝、无签名能力、余额不足或准备过期时明确提示并保留草稿。不得回退signAndSend、主网或跳过既有验签/复核。签名前过期可由用户重新准备，发送不确定不可包装成重发按钮。
- 显示准备中、等待钱包、发送中、待确认、确认成功、明确失败。发送后保留原签名与回执；超时/未知结果显示“结果待查询”，只查询原签名，不自动重签/重发。
- 结果不依赖编辑弹层存活。刷新后提供最小“查询待确认记录”入口，复用已有存储与recover/check，仅查询，不自动签名或发送；不做新回执管理中心。
- 已确认后调用既有readBack并刷新公共流/对应作者历史。读回暂不可得时保留确认与签名，给读取重试，不把它改成交易失败。只在作者与正文均未变时清理原草稿，不能清掉后来编辑的内容。
- 正文纯文本显示；Explorer限固定官方域名并带cluster=devnet。保留现有三语言/主题/手机布局，不改Logo或产品定位。

## 最小验收

以STATUS的W01/W02/W03为准。最终由用户在一个实际支持签名的钱包完成一笔Devnet交易，留原签名、确认/Explorer与刷新读回证据，逐项记录版本和时间戳，由用户确认。钱包名称/版本、浏览器Ed25519支持目前不确定，实际验收时记录，不将只读连接成功当作可签名证明。

Cline本次交付只含页面实现、现有检查和可复现截图，不代替用户实际签名、不声明真实广播已通过。先供Codex复审，候选上线和真实钱包步骤随后安排。现有线上v0.1继续服务。

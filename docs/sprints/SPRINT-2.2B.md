# SPRINT-2.2B：单条Devnet发布（交易准备契约重写）

## 为何重写

用户Chrome Phantom实测先出现能力包装对象误判；该R1已用一轮修复和一轮确认完成。随后真实截图显示可准备但签名返回“签名交易消息与准备快照不一致”。旧工单只要求钱包签名前后字节不变，却没定义准备阶段如何控制钱包自动优先费，与Phantom已公开的签名时自动插入费用指令行为不匹配。旧单不能再追加第三轮修复；本文件重写实际交易准备契约，不给旧R1重置计数、不仅改编号绕过上限。

真实截图只能证明消息变化，尚未取到此次钱包返回字节，具体变化仍属未核对。Phantom官方依据：https://github.com/phantom/docs/blob/master/development-powertools/solana-priority-fees.md 。官方说明无已有签名、无预算/费用指令且大小许可的交易可能被自动插入优先费。该行为是兼容假设，不能把任意消息变化判成安全可接受。

## 本次目标与契约变化

在准备、估费及模拟之前完整定义Devnet计算预算和优先费。返回签名交易仍与同一准备消息严格逐字节一致，仍实际Ed25519验签；消息变化继续拒绝，不能放宽为“正文相同就发送”。真实验收仍为一条留言审阅→用户钱包签名→链上确认→刷新读回，STATUS的W01-W03不变。

旧契约：unsigned消息只有System零转账和Memo两条指令，签名前预算/价格未指定。
新契约：v0消息固定四条指令，顺序为SetComputeUnitLimit(400000)、SetComputeUnitPrice(0 micro-lamports/CU)、原System零转账、原Memo。计算预算400000保持足够的执行额度；它是资源上限，不是支付400000 lamports。价格0仅指定Devnet优先费为0，基础网络费仍由真实getFeeForMessage返回并展示，不硬编码估费或宣称免手续费。不更改主网策略，因为项目没有主网入口。

## 实现范围（Cline）

1. 先读AGENTS、STATUS、DECISIONS并检查git；保留用户规则/记忆/技能/钩子。当前只由Cline实现。
2. 主要只改src/message.ts及受影响的src/message.test.ts。复用现有kit的编码工具，按原生ComputeBudget程序构造无账户的两条指令（limit discriminator=2 + u32 LE；price discriminator=3 + u64 LE）。预算与价格设具名常量，不新增依赖或抽象适配层。
3. simulation和publisher都必须继续消费同一构造器/同一字节。validatePrepared重建必须自动纳入相同预算；不改publisher的字节一致性、验签、会话、费用/余额/高度复核、单次广播或回执规则。若有直接相关的既有断言假设两条指令，可按四条新契约更新；不删真实安全断言或跳过测试。
4. Memo JSON、板级标记地址、作者单一签名槽、零转账、正文/大小校验保持。history现有解析器已支持前缀ComputeBudget且旧记录可读，不为本单修改读取器或历史协议，不做数据迁移。
5. 沿用现有UI/三语言/主题，不改钱包能力R1、不改依赖、不加后台/账号。不在前端自动接受钱包返回的变化交易，不重签/重发；用户在钱包手动改费导致消息变化时仍中止提交。

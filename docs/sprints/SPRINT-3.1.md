## 数据来源与信任边界

- 固定复用 `DEVNET_RPC_URL`、`DEVNET_GENESIS_HASH` 和 `message.ts` 中的公开程序/标记/协议常量，不更改 app=cyber-guestbook、v=1、board=public-devnet-v1。
- `getSignaturesForAddress` 查询的是包含指定账户的交易；签名列表只是候选，不能相信它的memo摘要就是本板有效正文。
- 公共流查 `MARKER_ADDRESS`；作者历史查经过地址校验的作者公钥，再执行相同本板协议校验并要求解析作者等于请求作者。不得只过滤已加载公共流，也不查全网Memo。
- 每次公开读取/重试操作先校验Devnet genesis；同一操作使用confirmed。交易读取使用encoding=json与maxSupportedTransactionVersion=0，接口类型先核对本地@solana/kit 8.6.0声明；不要把实验中的版本1请求参数直接照搬。
- 依赖可信RPC返回的已确认交易及其签名账户结构；不声称浏览器独立验证了共识或所有Ed25519签名。confirmed不等同于finalized。

## 解析契约

输入为查询签名及RPC原始交易；边界接受unknown并逐层验证，不能用类型断言替代校验。无效候选给出可测试的拒绝原因，不使整页崩溃；null/缺失元数据等不可验证结果与明确无效交易分开。

当前协议兼容范围保持阶段0及现有构造器：

1. 只接受version=0、meta存在且err=null；查询签名与transaction.signatures[0]一致。唯一签名槽、签名为有效base58且解码64字节、非全零，header声明恰有一个required signer。作者只能取静态账户首个付款签名者，不取JSON里的自报地址或日志文本。
2. 验证header、静态地址、索引范围与整数类型；当前不支持ALT地址表、legacy、多签、内部CPI留言或其他版本，明确记录为不支持，勿把它们解析为本协议。不得把loadedAddresses当成签名者。
3. 接受零至两条前置ComputeBudget指令，再跟一条System零转账和一条Memo4。沿用实验兼容的设置：ComputeBudget只接受不重复的SetComputeUnitLimit/SetComputeUnitPrice、正确数据长度与无账户；不得因钱包增加这两条就误丢有效留言。其他额外指令/未知布局不放宽猜测。
4. System指令解码必须是Transfer（u32=2）且u64金额精确为0、恰好两个账户，来源为付款作者、目的为固定板级标记；仅“账户列表里出现标记”不够。
5. Memo4指令恰好引用该作者签名账户。data用SDK正确base58解码、严格UTF-8解码（fatal），解析成非数组对象；严格四字段app/v/board/text及对应值和类型，不接受额外author等字段。限制原始Memo数据量（沿用实验1024字节上限），正文保持原文，不trim改写；验证well-formed Unicode并复用140 grapheme/560字节/非空白规则。
6. 输出至少包含signature、author、text、slot、blockTime、feeLamports。金额/slot按SDK实际类型安全规范化，不做有损Number强转；blockTime允许null，不制造时间。slot是slot，不写成区块高度；费用来自meta而非固定5000。

阶段0公开真实夹具包含前置ComputeBudget和80000 lamports费用，应加入回归。需要额外钱包交易布局支持时另提证据与契约，不自行放松作者校验。

## 读取接口、分页与请求预算

导出一个最小可注入RPC的客户端工厂及纯解析入口，具体类型命名可顺应现有代码，语义必须清楚：

- `readPage`：输入查询范围（board或author）、可选before游标与AbortSignal；返回已验证messages、原始候选扫描数量、过滤数量、不可得/读取失败签名及原因、nextCursor、sourceExhausted。author范围携带并回显作者地址，供3.2隔离状态。
- 提供对返回的不可得签名进行显式重试的入口，复用同一解析器与范围校验；最多20个唯一签名，不因为游标前进就永久丢掉先前null/失败项。也可提出等价的保留/重读方案，但必须有测试证明不会静默丢失。
- 每次readPage只查一页：默认10条、硬上限20条候选；交易详情最多并发2个，候选先按签名去重。普通默认页最多1次genesis+1次签名列表+10次详情；显式重试同样有界。不后台轮询、不递归扫到凑够10条有效留言、不无界重试，不使用429快速循环。
- caller取消或超时（每个RPC默认10秒，整次操作最多30秒）停止后续派发，并取消已发请求的页面等待；晚到结果不能被当成成功返回。错误类型能区分取消、超时、RPC/限流、错误genesis、无效地址/游标和游标无进展。
- genesis或签名列表请求失败应报告操作失败，不能回退空数组。单笔getTransaction返回null或请求失败可返回部分成功，但必须保留对应签名与原因，重试仍可恢复；meta=null同样不得算验证通过。明确失败交易可过滤，不能伪造正文占位项。
- nextCursor取原始候选页最后一个有效签名，不能取最后一条成功解析的留言；即使整页都是无关/失败交易，也能继续。页内/跨页去重按signature，不按正文；同一人两次同文是不同留言。
- 至少空候选页可标sourceExhausted=true；达到预算、结果少、解析后空、重复游标或仍有未解决交易均不等于“全部历史已读取”。重复/无进展游标明确报错，不能死循环。sourceExhausted仅表示此RPC查询范围的可用候选扫描结束，不保证链上永恒可得。
- 保持RPC最新到最旧顺序；异步完成顺序不能打乱它。同slot不按时间戳臆造顺序。刷新从最新页新查；不依赖浏览器缓存/钱包连接，3.2再实现跨页合并、状态隔离与界面生命周期。

## 必须验证的行为

| 类别 | 实质性覆盖 |
| --- | --- |
| 协议/作者 | 真正两作者夹具；有/无ComputeBudget；付款签名、Memo账户、标记转账；错误程序/金额/板标记/协议/额外字段/签名/索引拒绝；不支持的版本与ALT不误收 |
| 文本 | 中文、emoji/ZWJ、原文空白保留、空白及两种超限拒绝；非法base58/UTF-8/JSON及畸形数据不让整页崩溃 |
| 查询范围 | 公共查标记、个人查作者地址；作者历史分页不依赖公共首页已加载内容；无关转账、非本板Memo不混入 |
| 分页/去重 | 全无效页游标仍前进；原始尾签名游标；重叠/重复签名、相同正文不同交易、同slot稳定顺序；空页与预算未完不同；无进展报错 |
| 失败/恢复 | 列表错误不假空、交易null/meta缺失/单笔失败的部分结果与显式重试恢复；取消/超时后不再派发或返回迟到成功；错误genesis短路 |
| 预算/类型 | 默认及硬上限、并发不超过2、无自动无限扫描/重试；非法作者/游标在RPC前拒绝；真实SDK bigint/null类型和实际费用保留 |

先运行针对新行为的失败测试，再实现并保留实际证据；不通过删除既有断言获得成功。按lock执行typecheck、全部测试、build及git diff --check。未改UI，本轮无需重做真机布局验收；原真机未验证项保留。
